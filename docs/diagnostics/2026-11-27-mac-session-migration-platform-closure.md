# Mac session migration platform closure

Base: `252df0db52d244e43046e8c337ea1f299b453234`. Validation date: 2026-11-27.

Reproduction and expected result: create an owned legacy WAL database, run migration, interrupt at each publication boundary, and reopen the same migration request. Legacy committed body and the original file identities must survive. An external old SQLite process holding the same database must cause ordinary desktop startup to refuse with a close-old-app/retry message. Releasing that owned process must permit normal startup of the same database.

Darwin evidence: source-file `flock(LOCK_EX)` prevents this process's independent READONLY online backup (SQLITE_BUSY), unlike the assumed Linux behavior. A distinct SQLite connection holding BEGIN IMMEDIATE allows an independent READONLY backup in DELETE and WAL modes, and rejects a legacy writer until release. Using the write-transaction connection itself for backup remains BUSY. The product Apple source guard therefore owns a dedicated SQLite connection; publisher lockfile and non-Apple guards retain their original behavior. There are no borrowed statements, body/schema mutations, or COMMIT. Closing the owned connection rolls back BEGIN and releases the write reservation; NO_CKPT_ON_CLOSE and PERSIST_WAL avoid closing-time checkpoint/removal of preserved WAL evidence. Guard initialization errors fail closed and the owned connection/identity handle unwind on every return.

A second real failure was isolated by the unchanged suite: reopening retained main after source_preserved/wal_preserved before sidecars had moved makes SQLite look under an inconsistent basename. Before opening SQLite, Apple recovery validates original ready receipt, unpublished staged index, snapshot, session inventory and each main/WAL/SHM identity+hash. It rejects foreign files, duplicate locations and changed inodes. Only a proven incomplete preservation prefix is reversed, using no-overwrite rename and existing directory sync. Complete sidecar sets and published indexes are not reversed. A separate create-once apple-replay receipt preserves completed notification boundaries without replacing ready.json. Repeated interruptions at both reachable reverse rename boundaries are covered.

Host behavior uses public macOS libproc, same UID and kernel file identity matching (including hard links), for both original and retained database names. It ignores this process, refuses external handles and fails closed on inspection errors. It runs inside the ordinary storage preparation worker before the actual factory. It never terminates other processes. The scan is a point-in-time prerequisite and does not claim atomic exclusion or protection against future opens after guard release.
