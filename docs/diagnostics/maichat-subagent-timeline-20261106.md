# 子任务触发位置与本机会话新建入口

## 现场与复现

- 日期：2026-11-06；平台：Windows Qt，macOS 使用同一桌面视图。
- 基线：`d71652124c3ef6b50ed8cfcf9292579d1c1a771e`（已发布 2.2.52）。
- 用户截图显示两批审查子任务在全部父正文之后集中展示。报告电脑的实际运行二进制尚未单独核对；不把本机旧安装程序当作该报告版本。
- 隔离 SQLite 用例：父正文 A → 两个 spawn_agent → 正文 B → 第二批 spawn_agent → 正文 C；随后逆序交付子任务事件，并切换会话、重新打开数据库。
- 预期：每张卡片紧随对应触发调用，状态、摘要、完成事件只更新原卡片；加载历史与冷重放位置一致。较早触发消息尚未分页加载时，不在尾部展示其子任务。
- 另一个截图要求移除列表顶部大“新对话”按钮，在本机设备分组标题右侧提供与远端分组一致的小“＋”；空会话列表仍能新建，操作沿用原信号。

## 根因证据

- `AgentChatPanel::subAgentCardFor` 直接调用 `MarkdownView::addWidget`，未记录父消息/工具片段位置。
- 冷恢复先绘制全部已加载父消息，再由 `restoreConversationControls` 枚举子任务，因此卡片被统一追加到末尾。
- 子会话枚举继承存储的更新时间排序，不能作为触发顺序。
- 正式 `spawn_agent` 的持久化成功回执包含 `Started sub-agent <sessionId> for ...`；同一工具片段保存稳定 part ID，可复用现有数据建立精确关联。
- iOS、Android 与远端同步当前没有这套独立子任务卡片；其 question 投影是另一条已按片段时序排序的路径。本次不扩展移动端协议。

## RED

- 日志：`.cache/subagent-timeline-20261106/timeline-red.txt`、`local-create-red.txt`。
- 构建与 PE 119 项检查在执行控件前通过；正式用户程序未停止或替换。

## 修复

- 将成功 spawn 回执的子会话 ID 与父消息/part 绑定，并随保留页面保存。子会话元数据晚到时仍保留绑定。
- spawn 独立形成工具组；卡片、消息条目索引和提问时序锚点一起插在该组之后。状态与摘要继续更新原卡片。
- 没有可见回执且历史尚未完整加载时不补尾卡；子任务创建时间较新也不能证明触发位置可见。当前页以外的子任务不读取摘要历史。
- 直接宿主 API 创建、没有工具回执的子任务，在完整父历史内保留既有尾部展示方式。本次不改 Core API/存储或同步协议。
- 本机新建使用真实 viewport 内按钮，与远端共用设备标题的 24×27 命中区域；新建信号、目录选择及远端路由保持原实现。空账户也保留本机设备标题。
