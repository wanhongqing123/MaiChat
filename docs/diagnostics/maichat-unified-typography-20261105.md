# 全应用文字与 Markdown 字号统一

2026-11-05；起点 main / eee43402 加原有未提交工作，保留其他功能修改。

## 用户操作与预期

从“我的 → 偏好设置 → 字体大小”选择标准、大、特大或跟随系统。标准正文及输入框
统一为 16pt/sp，大与特大对应 18 和 20；默认采用标准，保留已明确保存的选择。
各页面同类文字使用相同系统字体、字号及字重，字号只缩放一次；更改后返回 IM、
创作中心、联系人、云盘和设置，都应立即采用同一比例，输入草稿、选区与导航保留。

Markdown 普通段落、列表、引用和表格以当前正文为准。标题相对正文放大，粗体/斜体
保留语义，代码保留等宽字体。三端共用 16 的标准正文、字号比例、颜色及间距定义，
桌面另保留已有整体界面缩放。原文和代码复制内容不改写。

验收使用同一份中英混合正文、标题、粗体、斜体、代码、表格、引用和 br 样本；检查
标准→大→特大→恢复标准的字号与布局，输入框文字/选区不丢失，横屏与长文本可阅读。
先运行并查看 iOS 模拟器正常 Root，再安装真机，最后检查 Android 正常 App；Qt 使用
同一 Markdown 文档与真实组件截图。缺少连接的平台如实记录，不替代实机验收。

## 已定位的差异

194 把 iOS 固定 16/14 字号替换为系统 body/subheadline（标准通常 17/15），且 Markdown
IM 与创作中心分别使用不同标题/列表/表格字号。iOS 正式页面有 431 处 font modifier，
固定文字字号与动态样式混用；UIKit 输入框另算字号。Android Markwon 标题比例仍以
14 为分母，而正文已是 16，且部分 span 使用独立绝对字号。原预览不足以证明全部页面
采用一致文字规则。这些差异需要收敛到公共呈现策略与平台字体适配。

## 深色模式复现与根因

用户提供的 2.2.4 (194) 截图：在“我的 → 主题色”选择深色后，消息和联系人仍有
整片白底；“我的”昵称、云盘空间/文件夹名、创作中心普通正文呈深蓝，落到黑色或
深灰背景上难以阅读。切回浅色时文字可读，证明不是消息内容缺失。

`RemoteIMStyle.panelBackground` 固定 `Color.white`，`textPrimary` 固定深蓝 RGB；
各系统原生页面已经随 `preferredColorScheme` 变深，自定义列表和 Markdown 尚未
同步替换这两个颜色。同时 `ChatNavigationHost` 新建的 `UIHostingController` 没有
继承外层自定义字号环境，因此消息列表和详情可能忽略外层设置。

## 实现

- `MaiChat/Presentation/typography.json` 统一定义 16/18/20 档位、语义角色、两种主题
  的前景/背景和 Markdown 比例；生成 Swift、Java、C++ 纯数据，`--check` 检查漂移。
- iOS 正文、列表、表格、输入框共用 body；行内解析缓存只保存语义，代码字体在
  呈现时求值。UIKit 输入框保留实例、草稿和选区。原生导航容器显式传递字号、
  Dynamic Type 和主题；原生导航标题也接入标题角色。原先固定的白色面板和深蓝
  正文替换为动态配对颜色，表头、代码、引用和 callout 同步适配。
- Android 页面选择生成的角色；文字、输入控件和 Markwon 使用同一 Configuration
  倍率，以 PX 一次换算，避免 Android 非线性 SP 重复缩放。字号新增特大，标准为
  默认；主题和字号都参与富文本缓存失效。表格、代码、标题使用相同契约颜色/比例。
- Qt 标准正文改为 16，表格和列表同正文，代码为 detail。现有整体缩放保留；“我的”
  新增三档文字设置。QSS 改用语义令牌并保留原始样式，已有原生编辑器、Markdown
  和标签可原位刷新，输入草稿不丢失。桌面本次沿用现有浅色主题。
