# 本地 GGUF 作为 Agent 主模型

需求日期：2026-11-03。基线 `5216279a`；178 已安装、推理自测和 llama 工具已可用之后，
用户明确要求本地模型与 DeepSeek / GLM 并列成为主模型。本记录在实现前写明验收，
不能拿独立本地测试页或云端 Agent 调用 llama 工具冒充本地主模型。

## 可复现操作和预期

1. 创作中心“•••→主模型”只显示“云端模型 / 本地模型”两项（按后续明确要求）；云端保留上次供应商，本地按需管理 GGUF 文件，不暴露推理参数。
2. 导入一份支持聊天/工具模板的 GGUF，选择本地模型并应用。没有云 Key 仍可以配置；
   保存到所属账号工作区，不持久保存会随安装迁移的绝对沙盒路径。
3. 从正常输入栏发送消息，经过原有 send/steer、MaiAgent、MaiTurnRunner，最后由本地
   MaiModelClient 生成流式文本。第二条消息带完整历史；工具定义和工具结果走原 Agent 回路。
4. 真正由模型生成完整工具调用，原 Registry 执行后原样配对回灌，模型据真实结果继续回答。
   半截工具、无效 JSON、未知模板、上下文超限须明确失败，不执行半截调用或静默丢历史。
5. 生命周期取消应进入真实 decode 取消；活动任务时切换主模型仍被核心拒绝，保留原设置。
6. 重开恢复所属账号的本地选择；文件缺失显示可恢复错误，不悄悄改回云端。

## 设计边界

Responses / Chat Completions 是远端通信协议；MaiModelRequest / MaiStreamSink 是已有
供应商中立契约。进程内本地客户端实现同一契约，以 Local 标明执行方式，不通过虚拟网络
端点或工具自调用绕一圈。云端现有两种协议继续使用。普通本地 API、llama 工具和本地主
模型共用唯一 runtime 的驻留、互斥与取消逻辑。主模型优先使用设备可支持的 GPU，独立引擎自测保留 CPU 契约。

本轮先接文本多轮及工具调用。带图片历史或非空 projector 明确 NotSupported；普通独立
本地自测原有单图/mmproj 能力不受此声明替代。TinyStories 只验证英文引擎，没有完整
chat/tools 能力，不能作为真实 Agent 回路成功证据。

验证将区分：原生模板/parser 的确定性用例、真实小模型推理/工具闭环、正常 App UI、
实际 iPhone 安装启动。当前正在实现，尚未将任何未运行路径写成通过。
