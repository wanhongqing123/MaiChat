# 云盘文件查询与原件下载

2026-11-06；main / eee43402 工作区。用户追问：模型如何知道下载哪一个文件，并要求
补齐文件查询能力。现有 list_media 支持游标和目录，list_folders 返回目录树；下载要求
从查询结果取得 media_id。缺少按文件名查找的独立入口，靠模型逐页阅读全部列表不便。

复现：云盘第 2 页存在目标视频，另一目录又有同名文件。只让模型下载一个名字时，
应先搜到候选，区分目录、大小、类型和上传时间，再按明确的 ID 下载原件。
第一页没有结果不能被当成整个云盘没有文件；重名不能任意挑选；查询不得下载媒体。

实现约定：增加共享 C++ SEARCH_MEDIA 普通能力和 maichat_cloud_drive_search_media
工具。使用现有账号私有分页元数据及目录接口，不更改或部署服务。支持 query、
exact_name、media_type、folder_id 和 before。返回文件 ID、逻辑路径、类型、大小、
上传时间。按源页边界返回有限候选及明确的 has_more/next_cursor；未扫描完不能宣称
唯一匹配或没有匹配。三端宿主仅调用同一核心，保留账号生命周期及取消边界。

查询返回的 `cloud_path` 是云盘逻辑位置；下载成功返回的 `path` 才是本地文件路径，
避免模型把云盘位置直接交给本地读取工具。文件名按 UTF-8 字面片段匹配，英文 ASCII
不区分大小写，可要求完整文件名匹配。created_at 为上传时间（Unix 毫秒）。目录查询
是直属文件范围；省略目录则搜索所有目录。尚未扫描完时必须继续相同筛选条件，不能
宣称没有文件或只有唯一候选。工具说明要求保留重名候选、根据用户指定目录等核对，
仍不明确时询问用户，不猜测 ID。

QA 与修改前快照：`/private/tmp/maichat-cloud-query-20261106/`。
