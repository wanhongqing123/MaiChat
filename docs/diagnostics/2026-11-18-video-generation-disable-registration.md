# 视频生成暂停后仍显示公开工具

日期：2026-11-18。平台：Windows 11、MSVC 14.44、普通 Qt 6.12 Release。
源码基线：`b69c65a74223eecf452ec3e6652f599f5578972a`，验证包含本记录对应的未提交修复。

## 复现与根因

打开创作中心的空会话，欢迎页仍显示“视频创作”，工具名为
`kling_bailian_video` 和 `minimax_video`。预期：视频生成已暂停，既不向模型公开，也不显示为可用工具。

`AgentController` 只把 Wan 视频和图片工具作内部注册，另外两种视频仍是公开注册。
`availableToolSpecs` 和 `StarterCatalog` 正确投影这个公开名单；原测试还明确要求两工具可见。
两工厂也保留实际新建任务路径。因此仅删除欢迎卡片不能修复可调用性。
本次没有用截图推断当前已安装程序的源码版本；安装产物比对由发布任务另行完成。

## 修复

- 桌面两工具改为内部注册。共享工厂对所有主模型不可见，旧宿主的公开注册也不能使其进入公开声明或模型分派。
- 工厂直接调用 `delegate/revise` 在凭据、旧任务读取、素材上传和 HTTP 前返回 `temporarily_disabled`，执行事实为 `NotStarted/None/started=false`，不产生无效付费批准。
- 能力查询明确生成暂停；已有任务的内部查询、恢复、下载和管理保留。MiniMax 本地 `validate` 继续可用。
- 桌面和移动适配器主指令及原公开名单断言同步为全部付费图片/视频生成暂停。移动修改仅涉及指令和原断言，没有改历史显示投影。
- `StarterCatalog` 保留公开声明投影，不增加工具名黑名单。

## 验证

证据位于 `.cache/video-generation-disabled-20261118/`。

- 欢迎页真实 RED：普通文本模型与支持图片的模型两行均因已暂停视频仍在列表而失败，2 条失败。
- 工厂真实 RED：37 条断言失败，涉及公开性、暂停错误、执行事实与凭据计数；这是断言数，并非 37 个独立产品缺陷。空凭据确保旧实现也不会触达供应商。
- 最终普通桌面程序及相关测试目标构建通过。工厂最终 0.13 秒通过；ModelStudio 工厂、任务通知与目录投影测试通过。
- 欢迎页两项指定方法含两模型配置：5 通过、0 失败、0 跳过，1.512 秒，使用真实 Windows QPA。
- 8 套基础测试各通过一次：Core、Store、InputQueue、TurnRunner、SessionRename、FilePath、Tool、ContextCompactor。
- 产品修复后的首轮回归另外暴露 4 条测试 oracle 误断言：`started` 为 `optional<bool>`，应比较值为 `false`，不能用 `!optional` 判断。这 4 条只出现在该轮，不属于产品缺陷，也不混入最初 37 条 RED 的计数。
- 供应商真实生成、在线诊断、付费探针均未运行；旧任务管理只使用自有内存记录。共享逻辑只在 Windows 验证，Android 适配器增量编译由其平台任务负责。
- 未替换用户当前安装程序。测试消费者通过缓存内 CMake hook 链接同一普通核心库，验证后恢复正常缓存配置；没有修改产品构建文件或增加依赖。
