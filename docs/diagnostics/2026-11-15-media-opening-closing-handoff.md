# 图片与视频首次/末次可见帧交接

2026-11-15。用户在 R5 私有 Mac 候选上提供三段实拍：图片开合末帧闪、视频先小后大、全屏关闭出现还原小窗；图片共用路径亦由用户报告在 Windows 出现。运行私有候选 PID 64730 未被开发者退出或替换。

## 根因与修改

- 视频普通入口先 `show()`，随后解码尺寸回调再 resize。新增普通 `prepareAndShow()` 入口，沿同一播放 worker 在隐藏状态准备实际尺寸后首次显示；MainWindow 本地/云视频和工具备用宿主复用。错误会进入原有可见错误态，取消与排队元数据按打开代次拒绝迟到显示；普通 QWidget.show 语义保留。
- Mac 关闭在触发原生退出后才隐藏，不能阻止 AppKit 先取到还原窗口像素。现在仅在真正开始关闭退出前保存原 opacity 并撤去像素，保留 DidEnter/DidExit/delete 顺序，支持同组件再次显示。进入全屏尚未完成时提前置零曾导致早关失败，原失败保留，修正后再验证。
- 图片原来由主窗快照动画结束后切换至独立预览，再等待 100 ms 删除快照，存在两窗口/绘制交接。现在从首帧起即为同一模态预览窗口，几何展开/缩回；不隐藏原缩略图、不调暗主窗，不再使用快照交接定时器。每个 resize 先落实图像视口几何，再缩放显示像素，原图不修改。

## 源与验证边界

Root 核对 R6 FULL9 的八个整文件旧/新 blob 与 MainWindow 三个函数的独立旧/新 SHA；只应用 FULL9 一次，保留 Root 的消息转发 eventFilter 修改。R5 MacLayer 生产 blob `367cca595db7f45c6454e0565c2dd95bddb0addb` 不变。未修改生产 Renderer/Media 后端或模型服务。

macOS 普通最终视频影响组 11/0、图片影响组 8/0，原三个症状的失败与中间失败分别保留。Root Windows 普通视频 8/0、图片 8/0；首个 Show 与稳定后 QRect 相同且仅一次 Show，图像在开关动画中保持相同原生窗口身份及像素。

Windows 独立不透明自有窗口完成三次开关，原生 compositor 点位采样 244 个、错误 0、外来遮挡 0，私有录屏实际完成。首个录屏命令遇到逻辑像素转换产生 2561 的边界，裁切到真实物理边界和编码偶数尺寸后重录成功，原失败保留。准确曝光夹具也曾在 parent 宽 0 时合成点击，现先选定对话并等待真实可见区域，没有借此修改生产源或放松同窗口/移动断言。

首 Show 的 QRect、原生 WillExit opacity、同一窗口身份与实际像素回归各自说明观测能力，不冒称 Mac 连续系统 compositor 帧全部已测。正式产物与公开发布另行记录。
