# 绑定 Session 的可见回复与 IM 转发

2026-11-15，Windows 普通 Release 构建。修复前基线为 `fa3e852a`，修改仍在工作区，尚未作为新版本安装或发布。

## 用户操作与预期

A 与 B 聊天，B 为 A 绑定本机创作中心 Session。A 的消息进入该 Session；Session 的中间回复正文、图片及最终回复发送给 A，并通过现有聊天发送代码在 B 的聊天记录保留一份。本地创作中心发起的同一 Session 任务也转发。工具调用、推理、内部协议封装不作为回复正文发送；创作中心保留正常显示。

## 根因与修改

- 原输出授权依赖某一条 IM 输入的回执，因此本地发起的轮次没有输出路由。本地发送、回车及停止还共用了撤销整个绑定的路径。
- 输出现在订阅绑定后新的 Core 正文提交和带原始 turn ID 的片段更新。输入回执仍管理输入队列与交互控制，输出沿账号、好友、Session、工作区和绑定代次核对。
- 使用原 `RemoteIMApplication::sendMachineTextTo/sendMachineMediaTo`，复用本地消息持久化和 SDK 发送，保持收发双方聊天记录及媒体/正文次序。停止只拦截准确轮次；解绑撤销旧订阅与迟到发送；本地发送保留绑定。
- 工具返回的可见 `MaiImagePart` 原来只有落库，没有及时的片段通知。Runner 现在在落库后立即通知，不等待下一次模型响应。只解析准确的 typed part 或原有文件交付回执，不读取任意工具 JSON 路径。
- 独立审阅还复现两处边界：新本地轮次在首个可见片段前失败，不能误伤仍在准备的旧视频；修改模型/思考强度，不能留下“已绑定”却移除输出订阅。前者增加真实终态 turn ID，并只撤销旧输入回执、保留排队的好友输入；后者保留配置变更中的订阅，工作区/账号/绑定身份仍在发送前复验，删除消息仅撤销准确消息的迟到输出。
- 按用户明确的可见内容语义，已完成并可见的媒体不因后续模型错误撤回；原始错误仍正常处理，不发送未提交的半截回答或错误详情。停止、解绑、清空及消息删除仍能撤销尚未派发的对应输出。清空历史会明确解除绑定并更新 UI，避免遗留旧上下文输入。
- 历史导入的模型安全封装原来直接进入正文和自动标题。标准存储现在提供真实导入来源，显示层只投影原消息正文。普通用户粘贴相同前缀仍保持原样；旧自动标题仅在来源及生成结果精确相符时只读投影，不改数据库和人工标题。

## 验证

自有临时数据库、离线模型与 IM 替身，未调用付费模型或读取用户数据库。

- 本地输出四例原失败；可见图片在下一次模型响应被阻塞时，好友输入/本地输入两例原失败。修复后正文、图片即时转发，B 本地各有一份。
- 普通 Windows `desktop_session_im_bridge_test` 最终 64 passed / 0 failed / 0 skipped，16.912 秒。覆盖原输入去重、队列、权限、媒体准备、停止、解绑、账号切换、历史导入及两项审阅回归。
- Router 19 项全部通过；Core 12 套与 console E2E 全部退出 0。
- 原始导入正文与模型角色保持不变；Panel 三例 5/0，Host 两例 4/0；历史标题同名粘贴、人工标题及真实来源条件均有对照。已查看自有界面截图，内部 JSON/封装不再作为可见正文。
- 旧标题读取由 Controller 分 16 条推进，最多同时处理四个会话，避免 GUI 一次扫描完整原史；没有后台裸 Agent 指针或数据库改名。
- 40 条原史跨三页的同一 Panel 用例同时核对旧标题、随后真实用户输入的显示标题与持久标题不变。分页按标准 API 的新到旧顺序读取，使用页尾游标。

原失败、测试环境缺少 offscreen 插件及旧断言/媒体次序变更均保留在私有 `.cache` 回执中。以上证明当前源码及普通构建的自有回归，不冒称两个真实账号、用户现装版本或手机端已完成整链验收。
