# Android 图片预览灰边与发送图片浅蓝外框（2026-11-04）

## 用户操作与预期

- IM 或创作中心点击图片进入全屏，完整图片等比呈现，图像之外不显示上下/左右灰色模糊背景。保持缩放、旋转、返回和来源过渡。
- 发送的图片缩略图只显示图片自身，不套文字消息的浅蓝背景、内边距或撑满整行的空框；时间与发送状态在图片外保持可见。文字气泡与引用内容保持各自样式。
- 以当前连接的 OPPO PKD130 / Android 15 验证；不发送测试消息、不清除账号或替换用户原有图片和草稿。

## 现场、来源与根因

开工源码 `440ae473`，工作区干净；手机实际安装 2.2.17(254)，仓库已合入协作者更新至 2.2.25(262)。本轮会重编当前共享原生核心，不能将旧 JNI 库当作当前实现交付。

灰边证据：此前同一真机预览截图 `fixed-valid-open.png` 为720×1604，原图等比约720×1562，上下各约21px。灰条整行 RGB(122,122,122)，与全屏白图背景的0.48 alpha吻合。MainActivity 的 page 已为黑底，但又覆盖一层铺满的模糊原图；前景未覆盖区域便露出灰色。Graphics 的原生清屏本身为不透明黑色。`gallerySnapshot` 同样叠加模糊背景，需避免翻页时短暂恢复灰条。

浅蓝框证据：用户截图与本机已有发送消息均为窄图在左、大片空蓝背景在右。`messageBubble` 无条件给外壳13×11dp内边距和发送消息浅蓝背景，非短文本又使用 width=0/weight=1；内部缩略图虽等比，外壳仍撑满剩余行。iOS 的图片没有该气泡背景/内边距，时间、状态独立排在图片外。

## 修复及验证计划

1. 移除正式图片页和过渡快照的模糊背景层，使用已有纯黑底；不以裁切或拉伸填满屏幕。
2. 图片外壳透明、零内边距、包裹真实内容，去掉缩略图额外上下边距。仅改图片分支；视频仍有单独宽度依赖，不顺带改动。
3. 图片行先给日期/状态预留空间，再按剩余宽度等比约束缩略图和配文/引用，覆盖窄布局及宽度恢复。
4. 真实 production preview 使用白色方图检验中心及四侧图内像素，随后检查余白纯黑；在旧安装上先运行同一用例，保留红绿截图。真实已有发送消息核验浅蓝外框移除及点击返回。
