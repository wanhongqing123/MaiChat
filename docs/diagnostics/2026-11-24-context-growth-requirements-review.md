# 上下文增长需求复盘与统一验收

日期：2026-11-24。基于用户本会话连续提出的要求、main 历史，以及当前尚未提交的正文保全候选。
本记录不表示下述全部改造已经实现，也不把本地测试通过写成现场或供应商验收通过。

## 最终目标

减少没有必要的模型输入增长和重复计费，延长有效工作时间，同时保留用户与助手交流正文。
Codex 是历史管理、计量和工具预算的代码参照；不能以“对齐”之名覆盖用户明确的正文保全和
渐进整理要求。调低界面百分比、延后触发阈值或频繁生成更短摘要均不等于达成该目标。

## 用户约束，按整个链路理解

1. 工具调用显示区分内置工具与 Shell，能够查看执行情况。这是显示需求，不代表工具原始详情
   必须在每次模型请求中全部保留。
2. 未发生正式上下文整理时，已发送的历史模型表示保持稳定，新内容只在尾部追加。
   不因轮次、图片数量或工具循环进度，修改旧图片标签、像素或工具表示。
3. 从首次回灌就控制工具内容：模型获得足够的结果、必要状态和精确补读定位；
   大日志和完整原文留在原史或工具输出存储，不因数据库保留而默认全部回发。
4. 达到容量触发条件时，先本地逐步整理工具输入、输出、错误及冗余信息，尽量只回收约 20%。
   达标即停，下次触发继续处理剩余工具内容，不一次把工具全部抹掉。
5. 用户最新要求是聊天正文不能丢。工具已无法继续缩减时，不自动用短摘要替代交流正文，
   不因 force、无工具补答、失败重试或 HTTP 413 绕过保护。
6. 推理、缓存和用量按实际模型协议处理。保留协议必需的签名或续接状态，不把它们等同于
   可自由删除的思考草稿；也不能把传输 JSON 的字节开销全部直接算成实际模型 token。
7. 会话仍放在每账号一个 agent.db 中。按 session_id 访问和原史补读即可，无需拆数据库。

## 证据已经证明什么

- 现场旧检查点约从 994728 估算 token 降至 110350，约减少 89%；独立用例复现无工具收尾
  退回整段摘要。此分支已在未安装候选中修正，不能以原史仍在数据库为由说正文没有丢。
- 目标会话原始归档正文约 110 KB，工具输入输出约 1.33 MB，另有思考与原生续接状态。
  这证明工具和宿主附带内容是应检查的主要来源；不等于当前请求内联了全部归档。
- Opus 截图显示约 39 万至 40 万的实际输入；可见 11 次调用费用约 $1.081。
  它不能只用本地估算解释，也不能把各请求输入相加当作窗口增长。
- MaiChat 用保守全量估算和只向上的倍率校准作容量判断，尚未使用与 Codex 等价的
  最近真实 usage 加未覆盖增量算法；JSON 元数据和续接字段的计量也有差异。
- Responses 已为目标 Claude 型号带缓存配置。没有 cached_tokens/cache_write_tokens 明细，
  目前不能认定缓存未启用或全部失效，也不能把“配置已发”当作高命中率已验证。

## 应作为一个需求交付的工作

### 先建立真实请求增长的证据

每个请求记录不含正文的计量快照：会话内顺序、模型/协议、检查点版本、可见正文/工具参数/
工具结果/宿主说明/推理状态/图片数量的分项字节、实际编码请求体大小、已发前缀是否一致。
接收实际 input/output、缓存读写、reasoning 明细；字段缺失保持未知。
请求顺序应覆盖工具循环、补答、失败恢复和压缩，不能只统计用户发消息的次数。
不记录凭据或完整提示词，不为测量额外请求收费模型。

### 从内容进入历史时限制不必要的增长

参照 Codex 的工具请求预算与模型历史策略共同限额，整理冗长通用说明和可省略的结构元数据。
必要的结果、退出码、取消/失败、执行影响、后台任务句柄及分页游标不得被裁成成功或丢失。
新表示在首次发送时固定；已发旧表示只能在正式整理边界替换，保持原始数据与准确补读。
不能仅把 64 KiB 换成 40 KiB 就声称解决：该现场保存表示超过 40 KiB 的总余量仅 260 字节。

### 以真实用量决定何时整理

最近成功供应商 usage 为基准，只估算尚未覆盖的新内容；完整记录其覆盖范围。
处理失败响应、缺 usage、工具结果后继、模型切换、检查点变化及重启恢复。
推理计量必须遵循实际协议，不能直接套用其它供应商的清理规则。
估算与实际占用、当前请求与累计消耗分开；显示和容量闸门用同一可信来源。

### 最后验证渐进整理与缓存连续性

主调用、工具后继、无工具补答、413、重试和 SQLite 重开全部遵守同一正文保护契约。
工具充足时两次触发均约释放各自触发前完整输入的 20%；工具不足时接受较少释放，不能动正文凑比例。
压缩外的历史模型表示逐项稳定；工具定义、基础指令和缓存路由的变化也应被观测，
不能只比较消息正文后就宣布整个请求缓存稳定。

## 统一通过标准

- 同一确定性工作负载逐请求对照改前与改后：解释每一项真实输入增长，消除重复或非必要内容。
- 聊天正文逐字保留，工具原文按精确来源可读取，执行状态真实；无工具收尾和恢复不能旁路。
- 大量图片、多工具、超过 8/12 张、连续两次整理、跨轮及重启均覆盖。
- actual usage 与估算独立可见；没有真实用量时不冒充精确，累计消耗不冒充当前窗口占用。
- 费用原因必须有实际缓存读写明细支撑。合成测试只证明正确性，不能证明某供应商实际命中率。
- 交付核对源码、构建和实际进程；未安装候选或未做供应商验证时明确注明。

本轮复盘没有修改生产代码、数据库或运行程序；既有候选及其它未提交工作保留。
