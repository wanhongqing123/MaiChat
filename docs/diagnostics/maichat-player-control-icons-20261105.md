# 桌面播放器控制图标参考对齐（2026-11-05）

## 复现与预期

- 基线：main `875156e7059e5464ca5318733dc3e2553c00b1de`，Windows v2.2.46。
- 播放本地视频，暂停并查看左下播放/下一段、右下全屏；点击全屏后再查看同一组按钮并退出。
- 用户参考为 `1793865573-123051033.png`、`1793865688-123051039.png`；本轮红圈为
  `1793875173-627349003.png`、`1793875251-627349008.png`。
- 预期：全屏使用左上/右下两段长圆角折线；播放、暂停和下一段采用参考的圆润实心图形，
  下一段的三角与竖条高度一致。保留原操作、菜单与间距。参考全屏态仍使用相同的两角图形。

## 定位

`MaiFfplayVideoDialog.cpp::videoControlIcon` 使用四角全屏路径，播放/下一段为没有圆角的填充多边形；
暂停竖条较窄且仅 18px 高。图标先以固定 2 倍生成位图，后续缩放再采样。
这与用户参考的轮廓不同，不能靠保持原路径、调整按钮尺寸对齐。

原始参考图实际为 2676×1505，分析前按比例归一，避免把应用预览缩放误当成控件尺寸。
归一至 2048px 宽后，参考全屏有效轮廓约 34px，当前约 26px；参考暂停/下一段中心距约 77px，
当前约 79px，因此不再改底栏布局。裁图与测量保存在 `.cache/desktop-player-controls-20261105/`。

## 修复与验收安排

将这些图形改为共用 SVG 资源，沿用 Qt 的矢量图标绘制路径，在实际设备比例渲染；进入/退出全屏
共用参考两角图形，由既有提示和动作区分状态。左右控制的可点击区域和键盘/工具入口保持一致。
修改后使用本地明亮素材运行现有播放器，查看播放、暂停、全屏和退出的真实画面，再核对运行产物。
Windows/macOS 共用资源；本机没有 Mac 构建入口，不将 Windows 画面称为 Mac 实机验收。

## 实际验证

- 发现截图入口与正常 App 的 DPI 设置不同：默认 `QTEST_MAIN` 没有开启
  `AA_UseHighDpiPixmaps`，图标会先画成 1x 后放大。改为在构造 QApplication 前使用与
  `src/main.cpp` 一致的 PassThrough、EnableHighDpiScaling 和 UseHighDpiPixmaps；
  不使用产品没有设置的默认 96 DPI。未增加镜像实现的图形断言测试。
- 本机正常 Windows 缩放为 150%；最终取证没有额外设置 `QT_SCALE_FACTOR`，
  1365×768 逻辑窗口对应 2048×1152 物理截图。另一次 225% 合成比例取证也正常。
- `controls-vector-chrome-cdb.log` 既有外壳/资源回归通过；
  `controls-final-evidence-cdb.log` 现有实际操作录制槽为 3 通过、0 失败、0 跳过。
  日志在 `.cache/desktop-player-style-20261105/`，真实运行进程为现有 Release 缓存中的
  `bin/MaiFfplayVideoDialogTest.exe`；启动前 `maichat` 已完成 windeployqt 和 95 项 PE 检查。
- `.cache/desktop-player-controls-20261105/evidence-final/` 包含播放、暂停、倍速菜单、
  全屏、控件隐藏和恢复窗口八张实际截图及 57 帧实录。已亲看阶段画面和逐帧缩略图，
  明亮素材视频区检查全部 57 帧通过。局部放大图来自真实截图裁取，未替换或绘制按钮。
- 新版本为 2.2.47，最终提交、全套发布回归、staging/ZIP smoke 和远端资产身份记录在
  对应 release manifest；旧 v2.2.46 资产不覆盖。本轮没有修改播放状态逻辑或共享核心。
