# Android IM 与 iOS 界面对齐、云盘加载文案（2026-11-03）

## 本轮要求与复现

源码基线 `98e92ae8`，手机上一版 2.2.13 (250)。用户提供 iOS 截图 `144115250159782623-1793716041-2674443658.png` 与 Android 实拍 `144115250159782623-1793716049-2674443659.jpeg`，明确要求 Android 对齐上方 iOS：

1. 好友页顶部多出“申请”按钮；iOS 仅在有待处理申请时在好友列表上方显示申请行与同意/拒绝。
2. 聊天页加号在 Android 打开浮动文字菜单，iOS 为输入栏下方的两行图标面板：相册、拍摄、文件、语音输入，第二行 AI 帮我回复。展开时占自己的底部区域、收起键盘；关闭后保留会话和草稿。
3. 顶部按钮形状和组合不同；iOS 是带浅底的远控显示器按钮及省略号，省略号进入真实远程排障菜单，不能接成普通远控冒充排障。
4. Android、iOS 云盘首次进入、目录加载及分页时，不显示“正在加载/正在连接/正在读取”这类可见加载文案；保留无文案进度指示、真实容量、错误和重试。

用户随后明确忽略照片方向问题，本轮不针对此反馈另改旋转处理。开始调查时手机创作中心存在用户真实运行任务，先只读源码和页面，不为验收触发付费请求，也不主动中止用户任务。后续远端已有的人像/EXIF改动随正常合并保留，未撤回他人修复。

## 源码证据与实施边界

- Android `MainActivity.contactToolbar` 无条件添加申请按钮，申请对话框是唯一受理入口；必须先将申请行放进列表，不能只删除按钮使功能不可达。
- iOS `ContactsView` 仅在 pending 非空时显示申请分区，入页和刷新时读取；按同样条件、账号代际和页面生命周期刷新 Android 容器。
- Android `showImageMenu` 原有四条浮动菜单与 iOS `ChatView` 的五格底部面板不同。语音输入在 iOS 只选择语音模式，不自动开启麦克风。
- iOS 省略号的真实动作是 `RemoteDiagnosticsView`；Android 未有相同 UI/协调器，需要核对已有 IM 协议与本地排障能力后提供真实入口，不能以假按钮或改名字掩盖缺失。
- 云盘修改限制在 Android `MaiCloudDriveDialog` 与 iOS `MaiCloudDriveView` 的可见加载文字，不改请求与账号/资源生命周期。

### Android 远程排障边界

新增 Protocol/Coordinator/Operation/Transport/Dialog，普通 IM 承载 `/diagnostics <uuid>` 与报告附件，不新增服务或模型代理。只接收同发送方、精确文件名/请求编号及 schema 的报告；下载与解析均限 2 MiB，按既有 iOS 白名单清洗。普通附件仍用原限制。只收集安全平台与消息元数据，原始日志、正文、凭据和环境变量不进入报告；未采集到的性能与语音阶段如实标缺。

每次确认使用独立许可；取消、离页、同账号重登等变化在实际 UI 线程发送闭包再次拦截，旧排队任务不会因重试复活。排障报告放在既有 IM 发出附件目录，发送只以真实 SENT 为成功，超时或入队未确认不显示成功。

30 项协议/协调器/实际排队写入许可测试通过（`.cache/remote-diagnostics-tests/combined-green.log`），包括 iOS 共享 fixture、匹配、大小/递归限制、脱敏、取消和账号代际。实际手机仅打开表单、核对未选接收人时确认按钮禁用并关闭，没有向真实联系人发送请求或报告；真实跨端回传尚未验收。
