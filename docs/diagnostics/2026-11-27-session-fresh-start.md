# 新版 session 从空记录开始

## 用户已确认的范围

用户明确选择“不导入旧历史，新版从空记录开始”，并限定为 session 存储；账号、IM、云盘不重置。无需再次确认该选择。此前“首次自动迁移”的发布后说明由此被取代。

## 设计与取舍

常规启动在共享核心选择新版索引，不读取旧数据库正文或执行旧库迁移。旧文件及 sidecar 原地保持；新索引使用原配置文件名加 `.v16`，JSONL 仍在同账户 `sessions/`，使用自己的 `.journal/<新索引名>.jsonl`。已存在的新索引或其权威日志优先，删除索引后也从同一日志重建，不复活旧历史。

此前已经使用 JSONL 的有效新版存储继续打开，避免每次升级清空新版产生的记录。旧的未完成迁移不自动恢复导入，保留原现场。独立的底层迁移诊断能力不作为常规产品启动路径。

不选择覆盖旧 `agent.db`，因为会破坏原件；不选择每次启动都重建，因为会丢失新版新记录。只让旧格式到新格式的首次使用从空历史开始。
