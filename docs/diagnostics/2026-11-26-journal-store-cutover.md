没有运行或修改现装程序、用户数据库、凭据或网络服务。

## 可复现需求

1. 用正式 `makeMaiSqliteStore` 写入会话、消息和工具快照后关闭。
2. 正文应出现在追加 JSONL；SQLite/其 WAL 只保留元数据和引用。
3. 删除自有索引，再用同一工厂打开，应从提交日志恢复相同数据。
4. 缺失/损坏正文来源必须失败，不得伪装空历史后重新采样或执行工具。
5. 新流式草稿仅在有界内存展示；旧库已有草稿、隐藏导入和原始输出迁移时完整保留。

## 实现边界

- 一个正式工厂、同一套 SQLite 业务算法；移除了产品中的旧正文写入与逐版本原地升级路径。
- 会话源为 `sessions/YYYY/MM/DD/rollout-<UTC毫秒>-<UUIDv7>.jsonl`，保留旧业务 ID。
- `sessions/.journal/<索引文件名>.jsonl` 保存跨会话有序元数据事务；它随既有安全发布器的
  `sessions` 目录一起发布，不建立第二套 SQLite 真相。
- 消息、片段、续接状态、检查点、冻结工具正文、专家回复和会话固定目录只存引用；
  普通字段通过 VIRTUAL 生成列回读。原始输出按 16 KiB 源记录分片，4 KiB 分页最多读相邻片。
- 完整记录先缓冲追加，事务提交前确认所有实际源文件 durable，再 durable 追加元数据账本，
  最后提交 SQLite。原有 `MaiRolloutLog::append` 仍承诺返回前持久化。
- SQLite 提交在权威记录之后失败，报告投影待重放，不能宣称业务回滚或重发工具。
- 部分尾部不截断，明确拒绝；尚不提供任意损坏源的自动续段修复。
- 事务只缓存刚追加的至多 16 个、每个不超过 64 KiB 的小字段，提交/回滚清空。
  事件读取另使用有界最新消息快照；来源标记只从当前已发布、选中的账本恢复。
- `:memory:` 仍使用同一 SQL/日志逻辑，源在自有临时目录，析构清理；它不是无磁盘模式。

## RED 与 GREEN

首次正式工厂契约在旧后端出现三项预期失败：数据库包含正文、没有会话 JSONL、删除索引后无法恢复。
新后端同一用例绿色。另发现并用 RED→GREEN 修复了事件缓存保留调用方伪造只读来源的问题。

自有产物目录：`.cache/joint-storage-20261126/store-own/`。
`fast.ps1` / `journal-green.exe`：所有新增断言通过，覆盖：

- 无损非法 UTF-8/NUL、固定目录 insert-if-absent 赢家、原生记录 latest 回读和去重。
- 新草稿不落源；事件回调从内存读到草稿；关闭再开只见已完成片段。
- 普通伪造 origin 在普通、事件缓存、分页和重开读取中均不能授予来源。
- 缺源读取失败且输出参数不变；16 MiB 原始输出的有界跨片分页、不可变 ID、跨会话拒绝。
- 冻结模型输出赢家、已发布导入来源、旧冻结 SQLite 全字段迁移及删除索引重建。
- SQLite commit hook 注入发生在源提交后：确认投影待重放并通过 readBarrier 恢复。
- 部分源尾部打开失败，原始字节不变；取消迁移不改旧源，归档未完成 stage 后重试成功。
- 原生轮次状态与完成片段投影，初始 Pending 工具不能冒充完成 item；上下文及中断恢复。

`store-subset.exe`：原有 MaiStoreTests 的所有直接存储业务用例通过，含 CAS、分页、归属、
并发、恢复、专家通知、续接、冻结输出和旧版迁移；仅排除依赖旧静态库 MaiAgent ABI 的故障集成用例，
该用例仍保留在原测试中，等待正常构建运行。新草稿和非法 UTF-8 旧断言按已批准策略更新，
迁移用例改用冻结普通旧 DDL，不向正式生成列库写低版本号。

`purge.exe`：原有内存/SQLite 导入清理契约完整通过，保留当前、暂存与普通消息；
旧版本门禁同样改为独立旧源夹具，没有删除原场景。

## 交付审查修正

2026-11-26 独立审查后补充并通过以下回归：

- 用 50 MiB 元数据真实触发权威记录的 64 MiB 拒绝：失败不新增字节、不确认已回滚的 SQL，
  同一 Journal 实例随后可提交正常小事务。原先仅重新 flush 旧前缀会误确认，已做 RED→GREEN。
- 不确定追加必须在追加前 EOF 精确找到本次 type、ordinal、完整载荷且成功 durable 才能确认；
  重放尚未投影的完整尾部时也在读前和游标提交前确认 durable。
- 原生历史只投影当前可见导入；实时发布同步新增、替换同步移除旧原生行，
  暂存、撤销、被替代的旧正文和扩展行仍保留。
- 空 BLOB 使用独立引用标记投影为零长度 BLOB，区别于空 TEXT 与 NULL；旧冻结空正文迁移通过。
- 未知旧表即使恰与新原生表同名，也只归档，不据其建立新原生状态。
- 初始 Running 原生轮次没有结束时间、时长或结束区间；终止时最终 item 引用真实助手片段，
  结束位置来自实际记录，不将消息 ID 误当片段 ID。
- session_meta 写入已知 cwd/model/agent/父级/推理配置；未知供应商、账号身份及初始指令明确为 null。
  实际 developer 头出现后，在同一日志关联其原始 ordinal/位置与完整指令，不覆盖初始前缀。
