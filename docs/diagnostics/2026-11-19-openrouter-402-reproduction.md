# OpenRouter 402 复现与修复实验

## 操作与预期

本轮从 `01fb32684614e065e7c46800ea95c232a31b3417` 开始，产品代码等于 `f785e2c2bae85129774686125828d85b409fa82f`。用户要求实际复现截图中的 402 并修复；此前只完成分类保留，不把该旧结论当作已复现真实额度状态。

先由正常 Apple Mobile C ABI 消费者，在独立目录、合成账号和本地 Responses 服务下生成一份普通 Fable 请求。只含自造短提示、正常工具声明和产品指令，不读取私人会话。记录工具数、schema/指令字节和输入项数，不预设等于截图所见的工具数。

真实对照限定为同一个普通 `MaiModelRequest` 顺序调用两次：第一次保持默认 `maxOutputTokens=0`，第二次仅改为 1024；同型号、low、相同输入/指令/工具，无工具执行、工具跟进或摘要调用。普通 client 关闭传输重试，单次总时限 30 秒，并设置取消边界；不制造并发消耗余额。凭据仅从既有服务器受限字段读到内存，再经 stdin 交给消费者，不写入参数、源码或日志。

期望取得实际 HTTP 状态、终态、白名单 reason/limit_source 和 Retry-After。只留形状、状态和计数，不保存供应商正文、思考、签名或密钥。两个 operation 先后发生，外部结算状态会随时间改变，因此结果不同不能自动归因为输出上限。

## 先行源码观察

- 自动标题纯本地截取文本，无模型调用。摘要和同轮主请求同步串行；同会话忙标志保持到 stream 退场。
- 不同根/子会话可正常并发，供应商同 Key 也可能跨设备使用；未读取用户任务库，不能据源码可能性断言现场并发。
- 主请求仍默认省略 wire 输出上限；目录的 128000 用于本地上下文预算，不是实际发送值。工具跟进重发有效历史和工具 schema，本地上下文压缩阈值不等于供应商的费用预算。
- 已知 HTTP 402 后连接 RST 虽然不重试，但仍先返回 Network，丢掉已知 HTTP 状态。这是可独立验证的诊断缺口，不冒充截图完整 HTTP 402 的根因。

## 验收边界

只在实际分类证据支持后选择修法，不先降低所有模型的输出上限、全局串行化、修改充值/Key 限制或添加无条件重试。若真实请求未再出现 402，应明确其未复现，而用正常客户端的确定性本地失败用例证明对应恢复行为；不能把一次成功当作历史预算原因已查清。

因用户随后关注费用，付费 A/B 在执行前停止，本轮真实模型调用与密钥读取均为 0。已完成正常 C ABI 代表性请求捕获和普通 client 的本地对照准备：129 个真实 registry 工具、95258 字节、单条自造输入；本地验证两份请求只差输出上限。它不代表已复现用户账号当时的真实预算状态。

## 确定性缺口及修复

对已收到完整 402 头、正文截断后连接 RST 的同一正常客户端用例，旧生产实际 RED10：四项错误类别、四项 HTTP 状态前缀和两项合法等待秒数缺失。窄修后保留已知 HTTP 402；无法解析的 metadata 继续未知，不猜 in-flight，也不触发重试。合法数字 Retry-After 作为已收到的独立 HTTP 事实保留，超范围或任意字符串不回显。

该修复与测试已在 `94741f62235b20b4d63c8eda2ad186446bc9d395` 正常提交推送。Selector、完整 Core 十套（50.04 秒）及正常 Windows 产品门禁通过。Mac 单 TU 编译 0/2.280 秒、普通完整 App 链接 0/0.855 秒，Core archive 全成员逐字节核等。

该边界修复只防止已知状态被连接错误覆盖，不宣称解决账号余额、复现了原截图完整响应或实现了费用优化。没有修改输出上限、并发、自动重试、缓存配置、服务器凭据或模型默认值。

iOS 230 已安装，普通启动仍保留此前 Locked 的待解锁项；本轮修复尚未作为后继手机包安装。缓存参数、稳定路由标识和计费 usage 的贯通仍属独立后续工作，未冒称已上线。
