# 上下文压缩窗口余量对齐 Codex

## 操作与期望

用自造历史和确定性模型输入计数，从普通 `MaiContextCompactor::prepare` 和 Runner 入口复现：默认请求在原窗口 90% 以下不因目录最大输出很大而提前摘要；达到 90% 尝试整理，硬输入预算为原窗口 95%。压缩失败与原史读取沿既有合同，不能为腾出预算删除用户消息或拆开工具调用和结果。验证仅使用本地假模型/owned store，不读用户数据库或调用真实模型。

## 预算合同

令 `C` 为真实模型窗口，`P(C,p)=floor(C*p/100)`。默认有效窗口 `E=P(C,95)`；明确预留 `R` 优先取非零 `request.maxOutputTokens`，否则取宿主 `defaultOutputReserveTokens`，缺省为 0。输入硬预算 `B=min(E,C-R)`；触发与目标分别为 `min(P(C,90),B)`、`min(P(C,60),B)`。

百分比用商与余数分解计算，避免整数乘法溢出和先除再乘的精度损失。非法或无法形成正容量的预算明确拒绝；未知模型窗口保持不猜测。摘要子请求也受有效窗口限制，输出上限仍沿既有独立摘要策略。

不再把供应商目录的最大输出当作缺省必需预留，也不另扣固定 8192 工具余量：固定指令、工具 schema 和实际历史已参与输入计数。显式生成 cap 和本地 automatic 的宿主余量可以进一步收紧预算；wire cap 原值不改，不能预算夹小却发送更大的值。默认低于阈值时应保持完整原文、零摘要调用、零检查点推进。

对照依据为官方 [Codex ModelInfo](https://github.com/openai/codex/blob/6271f35f527bf7709b9af5e4e752e9f122706a17/codex-rs/protocol/src/openai_models.rs#L577) 的独立 90% 自动阈值和 95% 默认有效窗口。该工作对齐预算思路，不声称复制 Codex 的全部压缩协议、远端不透明状态、摘要格式或历史保留算法。
