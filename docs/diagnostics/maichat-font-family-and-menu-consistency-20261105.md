# 字体选择与“我的”菜单一致性

2026-11-05；基于 main / eee43402 和此前 195 工作区，保留其他未提交修改。

## 操作及预期

195 真机中切换“我的”、消息和创作中心，用户指出“主题色、偏好设置”等菜单文字
仍与其他页面不同。需要用同一正文样本比较实际渲染字体、字号和字重，不能仅检查
公共字号函数。各普通菜单和正文采用同一基准；说明、时间等只按固定比例缩小。

用户进一步要求“我的 → 偏好设置”新增字体设置。选择后，“我的”、消息、创作中心、
联系人、云盘及输入框均使用所选字体，保持当前字号档位；改变字号时，说明、时间、
Markdown 标题/正文等一起按比例变化。Markdown 强调保留字重/斜体，代码保留等宽。
切换不重建 iOS 导航或输入框，不丢草稿；Android 保留既有外观切换的草稿恢复路径。

提供各端可用的字体，不把不具备分发许可或未安装的字体列成可选项。共用字体资产、
许可、来源和选择标识，平台层只适配字体 API。以中英混合菜单/正文、代码和表格
核对选中效果，最后构建并更新 iPhone。

## 已定位

`MySettingsRow` 的 `.font(AppTypography.body)` 只加在图标上，标题 `Text(title)`
没有显式字体，原生 List/NavigationLink 仍可能覆盖上层字体环境。其他设置控件也
使用系统隐式字体。195 的验证主要核对字号函数和 Markdown，缺少菜单与正文的
实际字体对照，这一处不能视为已经全部统一。

新的回归需要直接比较正常 Root 内同一行菜单文字与创作中心正文在各字号/字体
组合下的实际尺寸，并查看截图确认字形与字重。

## 实际定位与处理

195 的系统字体对照没有得到字号高度不同的证据：标准、大、特大两处行高分别为
19.33、21.67、24pt。原实现仍保留了普通行不同的字重和前景色，并有原生控件隐式
字体；不能把用户看到的差异简单等同为字号不同。最初自动化停在重复按钮定位，
修正选择器后才取得该数据。

- 设置页文字显式使用正文/说明/时间等语义角色，普通主文字统一常规字重与正文前景；
  姓名等普通行统一正文基准，说明与时间继续按比例缩小。
- 新增共用字体目录 `MaiChat/Presentation/fonts`，直接分发校验后的 Noto Sans SC 和
  Noto Serif SC 静态字体及 OFL 许可。`SOURCE.json` 固定上游提交
  `f8d157532fbfaeda587e826d4cd5b21a49186f7c`、来源 URL、长度和 SHA-256。
  三宿主共用约 72.45MB 原始字体/许可，不在运行时下载，不复制微软字体。
- iOS 普通字体/输入框/导航标题共用选择与基准。`MySettingsText` 直接读取语义样式，
  避免原生列表再注入另一套字体；`AppPageTitle` 统一原生/自定义标题。此前仅修改
  UINavigationBar appearance 不能让实际 SwiftUI 标题采用所选字形，已移除该路径。
- 字体选项各自预览实际字形，页面和 Markdown 预览展示当前选择。代码保持等宽。
  表格语义缓存不存旧字体宽度，渲染时按当前字体测量，每次 body 只测量一次。
- Android 同一 Typeface 传给菜单、输入框和 Markdown；字体变化使富文本缓存失效。
  Qt 同时更新全局字体、原生控件和 Markdown 主题，布局键包含正文/代码家族，并在
  归还旧排版后再换主题，避免旧字形写入新键。Windows 只列出已安装的微软雅黑、宋体。
