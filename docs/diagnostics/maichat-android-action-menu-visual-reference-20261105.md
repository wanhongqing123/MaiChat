# Android 操作菜单按 iOS 实图对齐（2026-11-05）

## 复现与验收目标

起点 `a7c2d332`，工作区干净，手机已安装2.2.27(264)。用户提供 iOS「操作权限」展开的实际截图，指出上一版菜单外观仍未对齐。打开 Android 创作中心右上角更多，依次展开强度与权限；菜单应保留同窗交互，同时按参考图呈现：浅灰磨砂外层、柔和阴影、独立圆角选项区、中性灰副文、较细标题和较重选项、黑色图标及明确勾选。点当前值不保存，点其他值后仍在原菜单，关闭/后台/旋转保留既有生命周期门禁。

## 根因与设计

- Android 外层和菜单内容分别使用不透明白色 border，PopupWindow 的背景是透明 ColorDrawable，实际没有 iOS regularMaterial 的背景采样与相近软阴影。
- 展开区域直接 `setBackgroundColor`，为直角；参考截图显示独立圆角。
- Android 使用全局深蓝主文/蓝灰副文，标题600、选项400；iOS 本处使用黑色主文、中性灰副文，标题与选项均500。现有归一化24格图标在18/11/12dp容器中实际占比也偏小。
- 沿用原 PopupWindow 和稳定菜单树，仅换此菜单的背景、局部排版与图标。外层只采样其后方的 App 区域，低分辨率模糊后加浅灰材质，限定14dp圆角；不模糊整个 App，不落盘背景截图。菜单展开显示更多同一份背景，不拉伸原背景或重建窗口。
- iOS 截图还有「主模型」云端/本地行。Android核心已支持llama，但宿主未接通来源切换、持久化与随包权重，仓库缺约1.4GB正式权重；是否本轮扩展功能已向用户异步确认。不得补无实际能力的假入口。

## 验证计划

1. 保存当前已安装正常 App 的同操作截图，作为外观修复前证据。
2. 原383项行为回归，若新增背景处理测试则验证其确实覆盖图像/内存边界。
3. 当前源码正式打包并同包同证书原位安装；真机查看展开/切组/勾选、保存/恢复、横屏滚动及关闭，录屏核对无第二窗口或闪动。
4. 以 iOS 用户原图与真机截图按逻辑尺寸比较，不直接比较不同设备屏幕像素；记录源码、APK哈希和运行进程。iOS 未连接，不能宣称新增iOS运行验收。

## 实现与验证结果

- 外层改为一层区域背景 Drawable：只在打开时对 App 对应区域做1/8大小采样和三轮分离 box blur，叠加 `ARGB(232,244,244,244)`、14dp圆角和黑8%细描边。Drawable 提供圆角 outline，使原 PopupWindow 的20dp elevation真实投影；内容不再覆盖第二层白底。扩大菜单显示同一背景的更多区域，保持物理位置，不拉伸。
- 展开组选项为14dp圆角 `#F2F2F7`，标题和选项局部使用500字重，副文 `#848485`、主文 `#0A0A0A`、删除 `#FF3B30`。5份菜单专用 vector 修正可见图形尺寸；全局其他图标不放大，删除本轮替代且已无引用的3份旧资源。分隔线为1物理像素，菜单右边距由16dp改14dp，移除额外上下4dp留白。
- 背景捕获不持有 Activity/View、不写磁盘、不打印捕获内容；失败使用同灰底。绘制先铺不透明灰底，避免窗口可用高度增加后超采样区域透出未经模糊的背景。
- 像素回归先以纯灰 stub 运行，3项中2项如预期失败；实现后一次失败定位为测试窗口可见框只有320×470、手工decor却是400×800，测试要求y450落在402px捕获之外。已把Fixture真实显示设为400×800，保留所有原像素断言。测试覆盖真实源颜色透过磨砂、边界模糊、展开不拉伸、fallback圆角/阴影outline。
- 正式构建40秒、退出0；JVM386/386，失败/错误/跳过均0。原有菜单行为用例继续通过。没有原生源变动，Agent/GLES为此前重编并核对的同一共享核心。
