# desktop_computer 拖拽坐标核对

2026-11-15，Windows 11，2560×1600，150% 缩放。用户报告滑块操作漂移，要求检查工具坐标。该调查不以模型在聊天中对往事的自述代替实际调用记录。

## 现场记录

仅只读查询与用户截图时间相符的本机 Agent 数据库，限定当前相关 Session 的 `desktop_computer` 坐标字段；不导出输入文字、登录资料、原始能力 token 或聊天全文。数据库不修改。该 Session 有 19 条 drag 调用，实际均使用 `target=display`，显示器原点 (0,0)、边界 2560×1600。

逐条关联原观察 token 对应的 PNG，仅读取图片文件头与大小：19 张全部为 2560×1600，均与回执一致，大小约 0.6–1.7 MB，未达到客户端 2 MB 模型预览转换阈值。没有证据支持这组记录发生了窗口/整屏混用或本地预览尺寸转换。

## 原生落点实测

使用普通库和自有全屏画布，执行 `DesktopComputerController` 的整屏观察、归一化坐标转换及生产原生拖拽路径。没有操作浏览器或第三方验证页面，没有调用模型。

- 要求按下位置 (512,720)，原生 WM_LBUTTONDOWN 记录 (512,720)。
- 要求释放位置 (1791,720)，原生 WM_LBUTTONUP 记录 (1791,720)。
- 该配置下端点误差 0 像素；52 个原生移动采样的垂直偏差同样为 0。
- 使用原生消息自身的坐标并 `ClientToScreen`，不能在 GUI 稍后处理消息时读取“当前鼠标位置”代替原事件位置。初版探针因此曾测到 16 像素的观测延迟；修正的是探针，不是生产坐标代码。

生产坐标链路保持不变。普通调用和工具协议共用控制器：按观察边界将 0..1 比例转换一次为 native 坐标，Windows 在线程 Per-Monitor V2 DPI 上使用绝对 `SetCursorPos`。`dispatched=true` 只表示输入已派发，不能当作网页验证成功。

结论限于：当前配置未复现工具坐标换算或原生落点漂移，历史截图尺寸亦一致。尚不能仅凭验证未通过确定网站结果或模型选点的原因，也不据此修改 DPI 参数或加入“不要折算”的猜测性提示。
