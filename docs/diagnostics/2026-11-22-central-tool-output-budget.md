# 第七批：工具结果的统一模型上下文预算

开工日期2026-11-22；main基线38d25b9d叠加既有工作区改动。

## 2026-11-23 主线集成补充

下述早期动态预算实现已经补上请求前缀稳定性约束：64KiB 单项和聚合预算用于首次发送的新结果；已发送的完整表示及其补读参数按来源、型号和原始字段指纹固定，跨轮次与 SQLite 重开不重新分配。固定表示在最终准备成功后才保存，候选回调只读；原始补读载荷被淘汰也不会改写旧表示。

旧记录没有新执行标记时沿用原文，不因升级追溯截短。要进一步缩减旧结果，必须实际推进压缩检查点；未知模型预算已满则明确停止并保留结果，不通过缩短旧前缀腾位置。整合后的普通回归包含四项大结果后追加第五项、新用户轮次、SQLite 重开及未知预算耗尽。

## 复现和预期

最初使用当时的正式app_storage工具、971个自有缓存文件、真实Runner及自有模型捕获第二次请求。
旧实现实际返回364446字节，下一次模型ToolResult仍为364446字节，无原始补读句柄。
此例不访问用户AppData/DB，不是只测试参数验证。最小回归同时核对8192窗口、完整DB原文、
失败执行事实、已有Shell输出句柄、可选保留API不支持、旧历史和同批多结果。

最终合同：每个模型ToolResult有64KiB硬上限；未知模型窗口使用256KiB聚合回退预算。
已知窗口按实际95%输入余量保守分配字节预算，聚合安全上限4MiB，不以固定256KiB误拒
大窗口中合法的小条历史。按显式生成预留及去掉工具结果正文后的请求估计进一步收紧。
准备完成后再核对完整请求（包括摘要/最后提示）的实际估计输入预算。按剩余结果
分配，至少保留有界的有效JSON说明；无法容纳必要协议/用户原文时仍交由压缩器明确失败。
字节预算是从估计余量保守分配的上限，不冒称供应商真实token或费用。

## 实施合同

- 完整MaiToolPart.output/error和原执行事实仍原样落库、再广播，UI/原史不被模型预算改写。
- 在Runner buildContext送入压缩器前，为ToolResult构建有界投影；当前及旧历史均适用。
  用户消息、指令、调用参数、call/result配对和原opaque continuation保持。
- 大结果用已有ToolOutput保留API写原始字节记录；SHA256身份绑定会话、消息、片段、call、
  原字节与源截断事实，避免重建上下文反复创建重复记录。只有真正可读的句柄才向模型公开。
- 有效JSON包裹包含context_projection_truncated、original_bytes、retained_bytes、
  capture_available/capture_complete、preview_text头尾、必要的structured_fields、
  可用时output_id/recovery_tool/recovery_args，以及已存在的original_output_id。
  保留原工具preview_id等有界值，不把任意JSON自述当执行事实。
- 单条保留API上限16MiB：超过时只能保留有明确不完整标记的前缀，不能谎称完整。
  保留API失败/句柄已淘汰时，投影不伪造句柄，原史仍在；取消和已发生副作用不因截断变成未执行。
- 建议补读页大小随预算缩小，避免“读补读结果又被包装”的循环。压缩器摘要直接分块读原史
  的路径仍按其整个摘要请求预算约束，不声称它走ToolResult角色的同一个逐项上限。

先RED再挂Runner。纯UTF-8/非法字节预览由普通MaiToolOutput辅助API复用；不加库、MCP或服务。
第九批把真实app_storage改为默认摘要后，中心预算的原大输出夹具已换成独立自有
owned_verbose_inventory；不再要求存储工具故意输出971条路径来制造压力。原始结果
280690字节，在两种窗口中投影为33795/4074字节，保留完整原文补读、来源和单次执行断言。
同时透传有界的partial/skipped_lines等OCR完整性标量、存储精确性及分页next_offset，
避免通用投影丢失新工具的已知不完整状态。未知窗口聚合边界、大窗口300000字节合法历史、
纯UTF-8/非法字节、伪造包裹字段、保留接口失败及句柄淘汰均有定点覆盖。

最终普通Core八套加存储及纯截图可用性共10/10通过，8.66秒；完整证据与旧夹具调整原因见
