# 正式 JSONL 后端与 Skills 接入

## 用户操作与预期

1. 正常登录桌面，打开原有会话并继续对话。旧 SQLite 只读迁移，原文件及 sidecar 保留；
   数据准备耗时时显示响应中的进度与取消状态，失败不进入空白会话库。
2. 完成正文、思考或工具 item 后关闭重开。完成项及原始 Responses 未知字段可回读；
   只有增量、尚未完成的新草稿不进入持久历史或下一次模型请求。
3. 在自有夹具中移除派生索引，重新打开后可由追加 JSONL 重建，源文件字节不变。
4. 将 SKILL.md 放入用户或项目祖先的 `.agents/skills/<name>/`。目录只提供名称、描述和路径，
   显式 `$name` 或对应路径选择时才加载正文；同一输入快照跨工具跟进和重启保持稳定。

## 实现与证据

正式 `makeMaiSqliteStore` 使用同一套日志和索引核心。正文与二进制保留在
`sessions/YYYY/MM/DD/rollout-<UTC>-<UUIDv7>.jsonl`，SQLite 保存元数据与字节引用，
虚拟字段按账号根约束回读原文。事务账本位于同一账户的 `sessions/.journal/`。
日志提交先于索引确认与完成事件；索引故障不允许重执行已经完成的模型或工具。
未使用的早期 MaiRolloutOperation 原型已移出产品源码，备份保存在本次自有缓存。

旧版本 1..15 通过只读快照构建新目录和索引，发布前逐值验证，包括非法 UTF-8、NUL、
原始工具输出、隐藏导入与未知字段。取消后的自有半成品经身份校验后整体归档，原库不改写。
完成 ready 后按已记录的身份严格恢复发布，不覆盖外来目录。

实际 loopback SSE 接入正式后端的测试已验证：先完成 A，再收到未完成 B 与失败终态，
A 和原始未知字段关闭重开后仍存在；B 不进入 JSONL 或模型历史。移除自有索引后重建仍一致，
且 JSONL 字节不变。源正文缺失时后续采样次数不增加。

Skills 复用普通管理/读取 API 与单个 `skill_read` 工具，按 canonical 路径去重；重名保留，
只对无歧义名称自动选择。技能内容保持用户级上下文，不授予权限、不自动执行脚本。
技能目录提示固定到会话，显式技能正文固定到源输入；新输入可读取更新正文，旧输入不变。
工作目录改变时仅在新输入中提供新范围目录，避免重写既有基础前缀。

## 审查与回归记录

独立审查发现并修复三项：不确定追加失败的错误确认、原生导入索引可见性、旧库空 BLOB
的类型保真。追加确认现在保留 SQLite 写锁，以唯一事务身份及原始 EOF 第一条完整记录
核对本操作；不能把其它写者的后续记录混入证明。失败夹具与修正收据保留在 `store-own/`。
桌面行读取探针需包含新增只读源检查连接；仍保留单条消息/片段读取量的全部断言。
执行会话界面的终态检查等待实际 GUI 队列完成，仍必须显示“已完成”，不降低期望。

完整回归还复现两项实际缺陷：Windows 深目录迁移触发 MAX_PATH；普通历史读取漏掉
RAM 草稿，导致流式思考类型识别错误。前者在 Win32 API 边界统一转换扩展长度路径，
不改变领域授权路径、不改注册表；实际超过 290 字符的创建/追加/读/stat 及原深 TEMP
迁移用例通过。既有 FilePath/FileSystem 普通测试也通过。后者仅在成功验证持久正文后
合并同阶段的 RAM modelDraft 部分，不覆盖持久赢家或来源身份；Runner 与 Console 原用例通过。

原 ToolOutputRead 失败来自测试 PATH 漏掉系统 WindowsPowerShell/v1.0；同一二进制只修正
环境后通过，未据此改产品。旧 Runner 关于非法字节被替换的断言改为验证权威原字节保真，
模型请求的文本编码检查保留。
