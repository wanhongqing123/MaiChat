# 渐进整理工具详情，保留全部交流正文

## 需求与现场证据

用户指出第二次压缩后窗口占用约 10%，并明确要求：用户和助手交流正文不能丢；每次先逐步缩减工具输入、输出及冗余执行日志，约回收本次输入的 20% 即停。工具内容不足以回收 20% 时，正文保留要求优先，不能通过删除正文来凑比例。

2026-11-24 只读检查用户指定会话的计量元数据，记录到检查点 revision 2：窗口 1,048,576，整理前估算 994,728 tokens，整理后估算 110,350，约减少 89%。因此不能只用“占用率不等于压缩率”解释现场。

用户提供的 `checkpoint-full-rev2.json` 为 680,896 字节，包含 meta、summary、references。summary 的六数组合计 42 条；references 共 2,213 条，其中 1,161 条是 tool_source，897 条是 path。旧 `desktop_process_start` 等名字出现在原史来源索引中，不表示工具重新注册。完整引用存档也不等于模型请求中全部内联的引用，原有模型侧引用预算仍适用。未把该文件正文或用户会话原文复制到仓库。

## 根因与复现

- 正常工具循环启用工具优先整理；最后补答撤下工具声明后，`session_history` 不再出现在该请求中。
- 旧逻辑据此拒绝复用工具优先检查点，重建原史并进入整段语义摘要路径；模型生成很短的六数组后直接提交，未继续遵守相对 20% 和正文保留要求。
- owned 内存与 SQLite 用例均复现：首次 18,500 → 14,800；撤下工具后再次变为 3,424，并额外调用 3 次摘要模型。原检查点和请求正文被替换，失败断言及原日志保留。
- 现场的普通六数组格式与这一路径一致。未导出现场请求体，不能声称已直接观测具体是哪一种补答触发条件；上述路径已通过独立确定性用例验证。
- 请求体适配还存在另一处正文裁剪：为解决 HTTP 413，会截断历史用户、助手及最终用户正文。它虽不修改数据库，却仍会丢失本次送给模型的信息。

## 修复契约

1. 产品的 MaiAgent 会话固定启用 `preserveDialogue`。用户、助手正文以完整原文字段进入请求，不依赖“原文在库、以后再查”来代替本次保留。普通显式语义归档 API 保留其原有契约，模型不能改变产品策略。
2. 正常整理只逐字段缩减工具输入、输出、错误详情，以及可省略的旧工具图片；执行身份、必要状态与原史定位保留。达到完整请求的相对目标即停止。正文、当前受保护输入不参与裁剪。
3. 工具已到必要骨架而不足以回收 20% 时，若仍适配硬限则保留正文并采用实际改善或延后；硬限放不下则明确失败，不自动总结正文、不安装不完整正文索引。
4. 新 `dialogue_preservation` 宿主标记认证本策略的表示。旧语义或部分正文检查点正常准备时，从原始来源补回全部正文；此前工具预览预算和图片省略标记按来源身份保留，不能把工具详情恢复。此前已封存边界也不倒退。
5. 旧检查点回补是一项修复，不以已经缩水的旧摘要为 20% 基数。未被旧检查点覆盖的新工具数据保持完整，只在恢复内容无法适配硬限时才继续逐步缩工具。来源指纹及 revision/CAS 校验成功后原子推进，失败时旧检查点保持不变。
6. 工具撤下后的最后补答走复用专用入口：不创建或推进检查点，不调用摘要模型，不启用任何工具权限；有效的既有正文表示与新尾部原样使用，超硬限或来源失效则明确失败。
7. HTTP 413 适配只裁工具回执、调用参数、旧思考/续接数据及原有图片降级项，始终保留用户和助手正文。普通用户 JSON 即使包含 `type: tool_output` 也不能被当作工具正文裁掉。不可适配的请求不重复发送；带真实原史能力的正常请求可额外尝试一次工具优先整理和重新计量，最后补答不会借此重写检查点。

## 验证记录

- 最后补答修复后：14,800 → 14,738，差异是撤下工具声明，模型消息正文逐字相同、检查点不变、摘要调用 0；内存与 SQLite 重开均通过。
- 正文占主导用例保留完整约 79,000 字节助手正文（含中文、换行和引号）及用户要求；工具不足以腾出 20% 时不总结正文。旧普通摘要迁移同样补回完整正文，摘要新增调用 0。
- 产品保护模式的正常两次渐进整理：900,000 → 约 720,000，925,000 → 约 740,000；小窗口及 SQLite 重开也验证约 20% 目标、预算不倒退和原史不变。
- 迁移用例验证已省略旧图不恢复、新工具输出原字节完整保留；超硬限、force、来源失效、非空工具声明均不能绕过最后补答边界。
- 字节适配 RED 证明旧逻辑会截正文并假装适配；修复版在工具可缩时保留全部正文并适配，纯正文放不下时保留完整请求并明确失败。真实 Agent 的纯正文拒绝仅发送原请求一次，不发送截断版。
- 已归档工具预览的字节恢复：原数据包 80,084 bytes，限额 72,075；不裁数据包中的正文，额外整理工具后只发送一次可适配请求并成功。
- 工具循环协议夹具改为给出真实原史读取能力，压力来自工具输入/输出，保证必要来源骨架可容纳；不再用过长用户正文验证有损摘要。仍验证两组各 20 工具、单图/多图的完整组来源、原始图片文件字节、SQLite 非法字节来源、精确原史读取与执行不重放。
