# PC Shell、Skills、用量和压缩对齐实施计划

> 按已获用户确认的 Codex 对齐要求实施，使用调试、测试驱动和分工审查流程；直接在 main
> 上保留既有未提交工作，不停止现装、不操作用户会话库、不增加依赖或 MCP。

**Goal:** PC 常用 Shell/Skills 的请求开销可控，状态栏显示真实最近请求用量，压缩基于
Codex 机制叠加用户要求，避免提前触发或一次丢掉大量正文。

**Architecture:** JSONL 已完成的 usage/window/source 作为事实源；发送前估算与显示分离。
Codex 的窗口计量、请求预算、工具生命周期、失败恢复和追加窗口为基础；在合法压缩边界上
优先缩工具、每轮相对回收约 20%，保留用户和助手正文。明确未知容量和缺失字段。

**Tech Stack:** 现有 C++17、SQLite、JSONL、Qt Widgets、Win32/POSIX；无新第三方。

## 已确认约束及核对结果

- 参考固定 Codex rust-v0.172.0，commit `3d86e43b075adeba2193ec5c22ac92f55afd82e6`，
  通过本地 git show 读取，不修改参考仓库工作区。
- 占用取最近主采样 `total_tokens`，不是会话累计，也不扣除缓存；最近摘要请求不能覆盖主窗口。
- 剩余百分比使用 Codex 的 12000 显示基线，窗口来自实际服务端或模型配置，未知不显示假百分比。
- `non_cached_input=max(input-cached,0)`；`blended_total=non_cached_input+output`，
  不是任意权重混合，不能用于上下文窗口占用。
- 未触发窗口替换时既有正文、工具结果和技能输入快照保持稳定；不对旧会话追改提示词。
- 新的上下文压缩逻辑必须先对照 Codex 的基础机制，再叠加约 20% 与正文保护要求。

  缓存、输出/思考与累计；准备/缺用量/压缩后未再次采样单独标记，估算仅用于发送保护。
  定点验证：真实 usage 事件、型号切换、会话切换和重开、tooltip 来源及实际截图。
- [x] Skills：对照参考的 8000 字符默认/已知窗口 2% token/可配置最多 10000 token，

  旧快照不改、未选正文不读。定点验证：大量技能、Unicode、分页、禁用隐式、重开与前缀。
- [x] 压缩和增长：复现 413 硬上限被错误 defer 的分支，修正为硬失败且不推进窗口；

  定点验证：软区可暂缓、硬区不能发送、失败不写检查点、同内容不重复压缩、两次各约 20%。

  条件下减少工具声明固定开销；工具仍按实际权限执行，原文补读和 PTY 生命周期不回退。
  定点验证：执行/输入/取消/大输出补读、发现后追加声明、未发现调用拒绝、会话隔离。

## 分工

- pc_usage_core：用量快照、Runner 实际回调、JSONL/codec 与普通查询。
- pc_skills_budget：技能目录预算、元数据发现与显式/隐式策略。
- pc_compaction_audit：压缩基础机制审计、已复现局部错误和增长计量回归。
- Root：PC 视图/同步适配、工具发现及集成、正常构建和交付。共享正常构建仅 Root 修改。

以上实现不改造账号服务，也不将 OpenAI 后台凭据部署宣称完成。
