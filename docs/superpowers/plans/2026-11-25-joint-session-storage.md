# 联合会话存储实施计划

**Goal:** 以每账号一个业务 SQLite 索引、追加式会话 JSONL 权威记录、独立运行诊断日志，
完成定制 Codex 表字段语义对齐，并保留 MaiChat 既有业务数据和可追溯窗口。

**Architecture:** SQLite 不复制完整 item 正文；标准 item_json 字段通过受限生成列真实回读。
会话、轮次、item、窗口及 usage 共享同一数据来源。现有工具、媒体、IM、来源绑定和队列
作为扩展索引保留；迁移只在新私有索引构建和校验成功后发布，旧源可回退，不动运行中现装。

**Tech Stack:** 既有 C++17、SQLite、nlohmann 和 Win32/POSIX API，无新第三方依赖。

## 已批准的约束

- 自定义 CODEX_HOME 实测结构作基线：26 业务表、185 原字段、40 索引；日志另有结构。
- 可以新增 MaiChat 字段，不遗漏标准字段语义。无来源的数据明确未知，不编造历史值。
- sessions/YYYY/MM/DD 与毫秒 UTC、独立 UUIDv7 rollout 文件 ID；旧 ses_/msg_ 身份不直接重命名。
- 外壳固定 timestamp/ordinal/type/payload；ordinal 只由权威文件追加方分配。
- usage 仅 token_usage_record 一份，含字段来源等级、原始明细、响应身份和三个累计范围。
- 完成 item 持久化、delta 仅实时展示；中断保留此前已完成 item，旧存量草稿不静默丢弃。
- compacted 追加可追溯窗口，保留原史；固定约20%和正文保全策略独立维护。
- UI 占用从最近服务端 total 与可信窗口计算，12K 显示基线可配置，缺失/推导明确标记。
- 小工具集/按需发现与显式 PTY 属于另一个内容发送优化任务，不把存储迁移宣称为节省 token。
