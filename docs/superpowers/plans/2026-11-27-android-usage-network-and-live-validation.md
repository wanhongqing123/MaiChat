# Android 用量、网络选路与真实业务验收

用户已要求继续补齐上轮验收发现的缺口并马上测试；沿用已讨论的服务端用量口径与网络审计方案，
直接在 main 工作区执行，保留既有修改，不新建分支、不提交、不发布。

## 可复现步骤与预期

1. 创作中心发送请求，服务端 usage 经 Core → 移动快照 → JNI → Android 界面。
   有值显示当前窗口实际占用、剩余比例、窗口和累计消耗；无值明确未知；切会话不串用量。
   延续现有 Core/桌面口径，不把本地估算包装成供应商实测，不硬编码 1M 或 12K。
2. 手机保留无公网 Wi-Fi 和系统允许的蜂窝，新公网请求选择可用路径。
   DNS 与 socket 属于同一请求租约；不关 Wi-Fi、不全进程绑网、不绕 VPN、不越过数据限制。
   在途 SSE 不因回调被杀掉重发；旧闲置连接不错误跨网络复用；局域网请求保留原语义。
3. 正常 App 语音、真实 IM 收发、云盘上传使用明确的自建测试内容。
   只给用户本人/自建测试账号发消息，不发付费模型任务，不清空数据；只删除本轮创建的云盘资产。
   录音需要真实麦克风授权；真实语音识别和静音/失败状态分别记录，不能用夹具代替真实识别。
