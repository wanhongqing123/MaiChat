# 桌面创作中心本地文件附件

## 需求与基线

用户要求在创作中心输入框直接拖入本地文件。产品基线为
`23288f8586f3a8cbd82a83d44a3eea0f57add6eb`；Root 当前后续提交仅修改诊断文档。
Mac 独占输入框实现，Root 负责窄补丁审查、Windows 回归及统一聚合，避免并行覆盖
已经验过的工具 receipt 显示、上下文居中和媒体逻辑。依既有任务授权推进，不新增用户审批步骤。

源码已确认 `AgentChatPanel` 的“＋”只有“选择图片或视频”，
`insertComposerMimeData` 也仅接图片/视频，普通文件不存在现成正式附件入口。

## 方案选择

采用普通文件卡片加本地路径引用，复用 QTextDocument marker、会话草稿、附件托盘和移除逻辑。
“＋”改为选择文件，选择与拖入调用同一验证和插入实现。直接插入裸路径文本虽然改动少，
但不能提供与媒体一致的可见草稿、移除和会话隔离体验；复制全部普通文件到导入目录会引入
额外存储与生命周期，本次不采用。当前方案不新增 Core 工具、权限或模型传输协议。

图片、视频沿用原导入和发送路径；普通文件只保存本地路径引用。
拖入不读取普通文件正文、不上传、不发送、不启动文件，也不改变正在执行的任务。
真正点击发送后，明确的本地文件引用随现有文本 prompt 进入 Agent，
由既有工具及其文件读取权限决定读取行为。界面不能把路径引用说成“已上传”或“已读取”。

## 数据与交互契约

- 只接本地存在的普通文件；目录、无效本地 URL 不作为附件，远程 URL 不冒充本地文件。
  普通文字粘贴保持原行为。文件卡片使用纯文本文件名。
- 普通文件 marker 与 image/video 明确分型，不进入图片/视频发送数组或媒体解码链。
  选择与拖入共享验证和既有附件数量约束，异步媒体导入计数不能绕过。
- 拖入多文件及已有文字时保留草稿；中文、空格、引号与换行文件名必须无损引用。
  文本 payload 使用结构化转义表达路径，不拼接或执行 shell 命令。
- 真正发送前重新检查普通文件；若引用文件已移动或删除，提示并保留草稿，避免静默漏发。
  被 Core 拒绝发送时同样保留。忙碌发送仍沿用现有 steer 路径。
- 提问答案只消费答案文字；普通附件与图片/视频一样保留在草稿，不被现有只检查
  image/video 的 `editor->clear()` 条件误清。仅附件不能伪装成文字答案。
- 会话切换保留各自文件 marker，不串到另一会话；移除、清空、撤销或析构不得删除外部源文件。
  普通路径不加入 `unsentImportedPaths` 或媒体目录回收集合；原媒体异步导入取消规则保持。

## 修改范围

预计仅涉及 `MaiChat/desktop/src/agent/AgentChatPanel.cpp`、对应头和
`MaiChat/desktop/tests/AgentPanelSessionTest.cpp` 附近。若共享文本编辑控件必须调整，
先核 IM 等消费者，不能为创作中心改变所有输入框默认行为。
不重构大文件，不修改 Core、模型输入工具协议、线上服务、现装用户 App 或已关闭的全屏诊断。

## 验收与交付

Mac 提供同一 owned 用例 RED/GREEN、普通组件构建与真实自有拖放截图，绑定源码及运行产物。
覆盖编辑区/viewport、多文件、混合图片视频与文档、中文空格及转义路径、目录/不存在文件、
已有草稿、移除不删源、跨 session、忙时不自动 submit、提问答案保留附件，
并在真正发送后的模型请求中核对引用内容及媒体分类。

Root 收到窄 hunk、before/post 和逐文件 manifest 后三方聚合，
复核普通文件不会落入媒体删除路径；运行 Windows 正常 App/相关 Qt 定点回归并查看实际截图。
单独记录两平台运行边界，不将 Mac 源码供件等同于 Windows 运行验证；
未明确安排新版本发布，不替换公开 4.0.2 资产。
